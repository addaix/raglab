raglab.bench#

Cross-run benchmark: the instrument for purpose-indexed memory (raglab#15, item 4).

The follow-ups of the memory design (CONSOLIDATE, SUPERSEDE, purpose transfer, DECAY) are each gated on an observed trigger. This module is what observes: it replays a workload of purposes through an agent twice, once cold (no memory) and once warm (with a PurposeStore), counting the source calls of each, and reports

  • sweeps_cold / sweeps_warm: retriever calls without and with memory (what memory saves),

  • recall: the share of the cold run’s hits the warm run also returned (what memory costs in answer quality: 1.0 means nothing was lost),

  • extractions: units kept per purpose after the warm run (the CONSOLIDATE trigger is “this exceeds a threshold”).

Cold and warm calls interleave on the same sources, purpose by purpose, so a source that changes over time shows as lost recall: that is the SUPERSEDE trigger, but so is plain non-determinism (an approximate index, a live API). Run the benchmark on a deterministic snapshot to read recall as what memory alone lost.

Hermetic and offline: pass any sources; nothing here calls an LLM:

report = cross_run_benchmark(sources, ["invoices 2023", "2023 invoices"])
report.sweeps_saved, report.recall

raglab.bench.loop_vs_single_benchmark(sources, questions, *, relevant=None, agent_factory=<function make_search_agent>, single_budget=None, **loop_kwargs)[source]#

Run each question through the agent loop and through a single discover; compare.

The single run is the same agent with single_budget (default one round, one pass over the sources) and none of loop_kwargs: no LLM roles, so no rewriting and no back-edge. The loop run gets loop_kwargs (formulator, evaluator, planner, budget…). Both count their retriever calls. relevant maps a question to the artifact ids that answer it, and adds recall against that ground truth; without it the report says how much of the loop’s answer a single discover already had, and what the loop costs in extra source calls. Offline when the roles are: pass fakes, or live sources for a real measurement.

Return type:

LoopVsSingleReport
